# Как опубликовать программу

## Важно: используйте только подготовленный чистый комплект

В исходной папке проекта сохранились `test-output/actual-real.json`, `independent-real.json`, `real-inputs.xml` и другие промежуточные файлы. Они также уже присутствуют в локальной истории Git. Удаление исходных Excel не удаляет эти копии.

**Не отправляйте существующий репозиторий проекта на GitHub и не загружайте всю исходную папку.** Старую историю я не менял. Для публикации подготовлен отдельный архив `kudir-ofd-github-source.zip`: в нём только программа, документация, лицензия и тесты на вымышленных данных, без `.git`, реальных выгрузок и результатов.

## 1. Создайте репозиторий

1. Войдите в GitHub и откройте https://github.com/new.
2. Имя, например: `kudir-ofd`.
3. Описание: `Локальная сверка Excel-выгрузок КУДиР и ОФД для Windows с понятным отчётом`.
4. Выберите **Public**, чтобы программа была доступна всем.
5. Не включайте создание README, `.gitignore` или лицензии: они уже подготовлены.
6. Нажмите **Create repository**.

Справка: [создание репозитория](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository).

## 2. Загрузите исходники

1. Распакуйте `kudir-ofd-github-source.zip` в новую отдельную папку, например `Документы\kudir-ofd-public`.
2. На странице нового пустого репозитория выберите загрузку существующих файлов (`uploading an existing file`). В непустом репозитории: **Add file → Upload files**.
3. Перетащите **содержимое** распакованной папки, включая `.github`, `.gitignore` и `.gitattributes`. Сам ZIP вместо исходников загружать не нужно.
4. Проверьте, что в корне будут `README.md`, `LICENSE`, `compare.ps1` и остальные файлы, а не лишняя внешняя папка.
5. Сообщение коммита: `Initial public release`. Завершите сохранение изменений.
6. Проверьте README на главной странице и вкладку **Actions**: тесты должны завершиться успешно. Локально они уже проверены; облачный запуск произойдёт после загрузки.

Справка: [загрузка файлов](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## 3. Добавьте удобный ZIP для пользователей

В разделе Releases создайте выпуск с тегом `v1.0.0` и названием `Сверка КУДиР и ОФД 1.0.0`. Прикрепите `github-ready\dist\kudir-ofd-1.0.0.zip` и соседний файл `.sha256`.

Описание выпуска можно взять из `CHANGELOG.md`. Пользовательский ZIP содержит программу, документацию и лицензию, без тестов. Его также можно пересылать напрямую.

## Лицензия

В комплект включена MIT: разрешено пользоваться, изменять и распространять программу, в том числе коммерчески, сохраняя текст лицензии и уведомление об авторских правах. См. [официальный текст](https://opensource.org/license/mit).

В строке copyright использовано название `KUDIR-OFD contributors`. При желании до публикации укажите своё имя или имя GitHub-аккаунта как правообладателя и пересоберите пользовательский архив командой из README. Не выбирайте другую лицензию при создании репозитория, если хотите сохранить подготовленные условия MIT.

## Что загружать не нужно

Не публикуйте исходную `.git`, старый архив «Сверка КУДиР и ОФД.zip», исходный `test-output`, реальные Excel, отчёты и скрипты старой проверки реальных данных. `.gitignore` помогает исключать новые файлы при работе через Git, но не удаляет ранее записанные данные из истории и не фильтрует ручную загрузку через браузер.
