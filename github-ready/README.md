# Сверка КУДиР и ОФД

Небольшая программа для Windows, которая сравнивает Excel-выгрузки КУДиР и ОФД и создаёт понятный HTML-отчёт: расхождения сумм, даты, исходные строки и подсказки для проверки.

**Свободное ПО под лицензией [MIT](LICENSE).** Работает локально. ИИ, API-ключи и интернет для расчётов не нужны. Исходные таблицы открываются только для чтения.

## Быстрый запуск

1. Скачайте ZIP с программой из Releases, если выпуск уже опубликован. Или выберите **Code → Download ZIP**.
2. Нажмите на архив правой кнопкой мыши → **Извлечь всё**.
3. В извлечённой папке дважды щёлкните **Запустить.cmd**.
4. Выберите КУДиР на первой вкладке и ОФД на второй.
5. Для поддерживаемых форматов нажмите **Автосверка всех кварталов** и выберите папку для отчёта.
6. В отчёте нажмите **Разобрать разницу** у интересующей даты.

Подробная инструкция с объяснением результата: [Инструкция.html](Инструкция.html). Откройте её локально двойным щелчком.

## Требования

- Windows 10 или 11 и Windows PowerShell 5.1.
- Установленный настольный Microsoft Excel с COM-автоматизацией. Excel Online и LibreOffice не заменяют его в текущей версии.
- Файлы `.xlsx` или `.xls` без пароля.

Python, Node.js и дополнительные библиотеки не нужны. Если запуск скриптов запрещён политикой организации, обратитесь к администратору. Скрипт запуска использует `ExecutionPolicy Bypass` только для своего процесса, не меняя системную настройку.

## Что делает программа

- Объединяет квартальные листы КУДиР.
- Сопоставляет безналичные поступления по дате продажи из назначения платежа, сохраняя дату документа КУДиР.
- Проверяет наличные по месяцам, когда они внесены суммой за период.
- Показывает общие итоги, сопоставимые продажи и печатные итоги отдельно.
- Разбирает расхождения: какие суммы сложены, где открыть ячейку и с чего начать проверку.
- Отдельно показывает прочие поступления и расходные операции ОФД.
- Сохраняет HTML и CSV с исходными строками для проверки в Excel.

## Поддерживаемый формат автосверки

**КУДиР:** листы `Квартал-1`, `Квартал-2` и т. д. Столбец B — дата и номер первичного документа; C — содержание операции; D — доход. Заголовки проверяются. Распознаются назначения:

- `Оплата наличными …` с двумя датами периода внутри одного месяца;
- `… по терминалу … за ГГГГ-ММ-ДД` для зачислений по картам;
- `Зачисление по QR коду … от ДД.ММ.ГГГГ`;
- `Выплата Гарантии качества …` как отдельное прочее поступление.

**ОФД:** один лист; K — дата создания документа, N — тип документа, Q — тип операции, R — сумма документа, S — наличные, T — безналичные. Заголовки проверяются. Ключ ФН/ФД берётся из D и J. Сумма документа должна равняться наличным плюс безналичным; иные способы оплаты требуют доработки.

В продажи входит «Приход» минус «Возврат прихода». «Расход» и «Возврат расхода» выводятся отдельно. Неизвестные назначения и ошибки не скрываются: отчёт содержит замечания.

Для других таблиц доступна **Ручная сверка листов** с выбором столбцов и диапазонов. Она сравнивает даты буквально, не объединяет кварталы и не распознаёт виды чеков автоматически.

## Как понимать результат

Разница = **ОФД − КУДиР**. Положительная — в КУДиР меньше, отрицательная — больше.

Расхождение указывает, какие документы проверить, но не доказывает отсутствие конкретного чека. Одна банковская запись может объединять много оплат. ОФД в поддерживаемом формате не разделяет безналичные на карты и QR: подсказка «если QR верны» является условным расчётом, а не готовым исправлением. Даты и суммы программа не исправляет.

Выбирайте одну организацию, сопоставимый период и все нужные кассы. Автоматической проверки ИНН двух файлов нет. Скрытые и отфильтрованные строки учитываются. Формулы перед сверкой рекомендуется пересчитать и сохранить в Excel. Для наличных, внесённых общей суммой за месяц, день пропуска определить нельзя.

## Конфиденциальность

Программа не отправляет файлы на серверы. Отчёты содержат исходные пути, суммы, назначения и идентификаторы документов: храните их как исходные бухгалтерские данные. Excel при открытии файлов может использовать свои внешние подключения; для сверки предпочтительны обычные выгрузки без подключений.

Не прикладывайте реальные таблицы и отчёты к публичным Issues. `.gitignore` исключает типовые выгрузки, но не очищает уже созданную историю Git. В этом комплекте нет реальных бухгалтерских данных.

## Тесты и сборка

Из папки проекта в Windows PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests-auto.ps1
```

Эти тесты используют только вымышленные данные и не требуют Excel. CI запускает их на Windows. Дополнительный интеграционный тест с установленным Excel:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\test-excel.ps1
```

Он создаёт собственный маленький `.xlsx` в `test-output`, читает его через Excel и проверяет неизменность файла. Графический интерфейс и COM-доступ к Excel не проверяются в GitHub Actions.

Пользовательский ZIP с лицензией создаётся командой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-release.ps1
```
